# Repository Guide

## Current State

- This is a working implementation, not a scaffold. All seven stages from `SPEC.md` are
  implemented: persistent chat + streaming (1), Exa web search with citations (2), PDF
  ingestion + hybrid RAG (3), multi-agent research (4), durable workflow (5), usage/cost
  controls (6), and admin/replay operations (7).
- `SPEC.md` is the source of truth; where it and `README.md` disagree, `SPEC.md` wins.
  `OPERATIONS.md` is the operational runbook. The two `*_EXPLAINER.html` files are
  standalone, beginner-friendly design docs — not build inputs.
- Use pnpm `12.5.1`; workspace packages live under `apps/*` and `packages/*`.
- Known divergences and gaps (documented in `OPERATIONS.md`): email verification is
  disabled in `convex/auth.ts`; model cost is computed from configured token prices rather
  than the gateway's authoritative bill; the app-owned reservation ledger is the enforced
  monthly cap. Do not assume live acceptance without running against a real deployment.

## Architecture

- `apps/web` is a TanStack Start app. Routes are file-based under `src/routes`; `src/router.tsx` connects TanStack Query to Convex, and `src/routes/__root.tsx` establishes SSR auth. `dashboard.tsx` holds the session sidebar, chat, PDF upload, research timeline, replay panel, and budget readout; `admin.tsx` is the admin page.
- `packages/backend/convex` owns the schema, functions, HTTP routes, and all component integrations. Mounted components in `convex.config.ts`: `@convex-dev/agent` (threads/messages/streaming), `@convex-dev/better-auth` (auth), `@exalabs/convex-exa` (web search), `@convex-dev/ai-budget` (metering/audit), `@convex-dev/rate-limiter` (frequency limits), and `@convex-dev/workflow` (durable pipeline). `auth.ts` requires the deployment variable `SITE_URL`.
- Sessions have a fixed `mode`: `chat` uses the single assistant with tools; `research` launches the durable plan → research → write → verify workflow. Only the writer's report streams to the thread; other role output lives in `researchArtifacts`.
- All generation and embedding calls go through the Convex AI Gateway via `@convex-dev/ai-sdk-provider`. Model calls are created with `ai.languageModel(...)` from `budget.ts`, which routes through `@convex-dev/ai-budget` for audit/dashboard, while the app-owned ledger in `budget.ts` enforces the monthly hard cap using reserve → settle. Prices are explicit in `budget.ts` and unknown models fail closed; extend with `GATEWAY_MODEL_PRICES_JSON`.
- RAG uses Convex file storage plus `documentChunks` with a vector index and a full-text search index, merged by reciprocal-rank fusion.
- Keep model/provider calls on the Convex backend. Never add provider keys to frontend env files; the browser only talks to Convex functions.
- There is no separate streaming transport: assistant output is persisted as stream deltas and read reactively by the UI.

## Commands

- Install: `pnpm install`.
- First-time Convex setup: `pnpm run dev:setup`; copy the generated public Convex values from `packages/backend/.env.local` into the web app environment when prompted.
- Full development: `pnpm run dev` (recursive package orchestration; backend plus the Alchemy-hosted web app). Web only: `pnpm run dev:web`. Convex only: `pnpm run dev:server`. The web port is `3001`.
- Build: `pnpm run build`. Focused web build/typecheck: `pnpm --filter web check-types`.
- Verify lint and workspace types: `pnpm run lint && pnpm run check-types`.
- `pnpm run check-types` covers web, UI, and infra but not Convex backend TypeScript. Check it separately with `pnpm --filter @convex-research-assistant/backend exec tsc -p convex/tsconfig.json --noEmit`.
- Backend tests: `pnpm --filter @convex-research-assistant/backend test` (vitest with `convex-test`, `environment: "edge-runtime"`). Test files live next to the code as `packages/backend/convex/*.test.ts`. `vitest.config.ts` includes a plugin that resolves an extensionless import inside `@convex-dev/ai-budget`; keep it when upgrading that package.
- `pnpm run check` is mutating: it runs `oxlint && oxfmt --write`. Use `pnpm run lint` for a non-formatting check and inspect changes after `check` or `format`.
- Deploy/destroy the Cloudflare web infrastructure with `pnpm run deploy` / `pnpm run destroy`.

## Generated And Environment Files

- Do not edit `apps/web/src/routeTree.gen.ts`; TanStack Start generates it from `src/routes` during dev/build.
- Do not edit `packages/backend/convex/_generated/**`; `convex dev` regenerates these APIs after backend/schema changes.
- `apps/web/src/env.ts` is generated and ignored. Change `apps/web/.env.schema`, then run `pnpm run env:generate` (also runs on postinstall).
- Convex deployment variables (set on the deployment, never in frontend env files): required `SITE_URL`, `GATEWAY_MODEL_ID`, `EXA_API_KEY`, `BUDGET_MONTHLY_USD_DEFAULT`; required for admin `ADMIN_EMAIL`; plus optional `GATEWAY_COMPARISON_MODEL_IDS`, `GATEWAY_EMBEDDING_MODEL`, `GATEWAY_EMBEDDING_DIMS`, `BUDGET_ALERT_THRESHOLDS`, `RATE_LIMIT_RESEARCH_PER_HOUR`, `RATE_LIMIT_CHAT_PER_MINUTE`, `MAX_DOCS_PER_THREAD`, `MAX_PDF_BYTES`, `MAX_PDF_PAGES`, `MAX_REPORT_TOKENS`, `RESEARCH_MAX_TASKS`, `GATEWAY_MODEL_PRICES_JSON`, and `AI_BUDGET_DASHBOARD_TOKEN` (gates the mounted `/aibudget` dashboard; unset means 401). See `OPERATIONS.md` for details.
- Local `.env*`, Convex `.env.local`, Alchemy state, Wrangler output, `.tanstack`, `.vinxi`, and build output are ignored; never commit credentials or generated deployment state.
